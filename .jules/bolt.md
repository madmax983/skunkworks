**[Removed pointer indirection in locus flocking hot loop]
**Learning:** Storing a reference (`&'a FlockingParams`) inside an intermediate struct (`PrecomputedParams`) used in a tight nested loop (`accumulate`) causes repeated pointer indirection per iteration (e.g. `pre.params.view_radius`). This forces the CPU to constantly fetch the value through the reference.
**Action:** Copy primitive/scalar fields (like `view_radius`) directly into the intermediate `PrecomputedParams` struct by value to improve cache locality and eliminate pointer hopping within hot physics loops.
