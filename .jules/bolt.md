**[Optimizing API Return Types Safely]**
**Learning:** Returning `String` for static symbols causes unnecessary heap allocations. Using `Cow<'static, str>` prevents this, but changing an existing `pub fn -> String` breaks the API boundary.
**Action:** Preserve the original `pub fn symbol(&self) -> String` and introduce a non-allocating variant `pub fn symbol_cow(&self) -> Cow<'static, str>`. Have the original method delegate to the new one via `self.symbol_cow().into_owned()`. This achieves zero-cost abstraction internally without breaking downstream callers.
**[Optimizing Iterator Collect Calls]**\n**Learning:** Using `.collect()` on `.filter_map()` iterators drops the original size hint to 0, causing `Vec` to perform multiple O(log N) heap reallocations. \n**Action:** When exact collection sizes are known (e.g. `num_hunks` or `lines_count`), replace the iterator chain with a manual `for` loop and pre-allocate the target vector using `Vec::with_capacity()`. This guarantees zero-cost abstraction for collection building.
**[Eliminate dynamic heap reallocations from flat_map(...).collect()]**
**Learning:** Chaining nested iterators with `flat_map` obscures the total length of the sequence from `.collect()`. This prevents `.collect()` from allocating the exact capacity needed upfront, forcing the underlying `Vec` to dynamically resize itself multiple times (O(log N) reallocations) as it grows.
**Action:** Whenever the final size of a nested structure is known mathematically (e.g., `rows * cols`), replace `flat_map(...).collect()` with an explicit `Vec::with_capacity(size)` and a loop using `push` or `extend_from_slice`.
