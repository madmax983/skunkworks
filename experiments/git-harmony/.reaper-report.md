# Forensic Analysis: `git-harmony`

**Specimen:** `experiments/git-harmony`
**Diagnosis:** Terminal Redundancy / Technological Regression
**Date:** 2024-05-23
**Observer:** The Reaper ☠️

## 1. Physical Examination

The specimen consists of a `ratatui` visualization and a basic audio synthesizer powered by `rodio`.
- **Structure:** `src/main.rs`, `src/synthesizer.rs`.
- **Dependencies:** `git-associates`, `ratatui`, `rodio`.

## 2. Pathology

### Terminal Redundancy
The specimen exhibits significant overlap with `experiments/git-cantata`. Both experiments aim to sonify git activity.
- **git-cantata:** Sonifies commit history. Features a custom audio engine (`src/audio.rs`) with FM modulation, ADSR envelopes, and timbre mapping based on file types.
- **git-harmony:** Sonifies `diff_workdir`. Features a primitive audio engine (`src/synthesizer.rs`) that triggers simple sine waves at fixed frequencies (A4, A3, E4).

`git-harmony` is effectively a "toy" version of `git-cantata`. While they visualize different *stages* of git (staged vs committed), the implementation of `git-harmony` is inferior in depth and complexity. It relies on the same shared crate (`git-associates`) but fails to build a unique or valuable experience on top of it.

### Technological Regression
The audio engine in `git-harmony` is a step backward from the synthesis techniques demonstrated in `git-cantata`. It lacks:
- Waveform variety (only Sine).
- Envelope control (fixed duration).
- Expressive modulation (hash-based micro-tuning only).

### Identity Crisis
The name `git-harmony` is generic and easily confused with `git-cantata`, `git-rogue`, `git-ghost`, etc. It fails to distinguish itself within the swarm.

## 3. Prognosis

**Terminal.** The specimen offers no unique genetic traits worthy of preservation. Its biomass (the `git-associates` dependency usage) is better represented by `git-cantata`.

## 4. Recommendation

**EXECUTE.** Move to graveyard.
